# SIZING — «СКОЛЬКО, ГЕНИЙ?»
## Визуальная концепция: физически построить ставку

### Что сейчас убивает интерес
Если пользователь постоянно выбирает `25 / 33 / 50 / 75 / 125`, режим всё равно ощущается тестом.

Основной навык Sizing — **ощущать геометрию банка**, поэтому взаимодействие должно быть связано с фишками и пространством.

---

# ОСНОВНОЙ РЕЖИМ — CHIP DRAG

## Экран

Верх:
`TURN · BTN vs BB · 42 BB`

Центр:
- board;
- крупно `POT 18 BB`;
- небольшая история линии.

Низ:
- стопка Hero `42 BB`;
- пустая betting zone в центре.

Заголовок:
**СКОЛЬКО КЛАДЁМ?**

## Жест

Пользователь тянет вертикальный slider, оформленный как стопка фишек.

Не обязательно делать настоящий drag отдельных 20 фишек — технически проще:
- `<input type="range" min="0" max="200">`;
- thumb скрыт;
- поверх slider визуально рисуется стопка фишек;
- высота/количество CSS-фишек зависит от значения.

Во время движения:
`7.4 BB`
`41% POT`

Меняются в реальном времени.

Кнопка только одна:
**ПОСТАВИТЬ 41% →**

То есть решение всё ещё явно фиксируется.

# РЕАКЦИЯ

После фиксации стол не исчезает.

Появляется горизонтальная шкала:

`CHECK ━ 25 ━ 50 ━ 75 ━ 100 ━ 150`

Точка пользователя:
`▲ ТЫ 41%`

Полупрозрачная рабочая зона:
`25–40%`

### Вердикт

**ЧИСТО**

> Здесь широкий диапазон хочет дешёво реализовать преимущество. 41% уже верхняя граница, но идея совпадает.

Фриковая Дама:
> **Фишки положены с объяснимой целью. Исторический момент.**

---

# РЕЖИМ «ЗАЧЕМ?»

После некоторых ставок экран не даёт verdict.

Вместо кнопок появляется 4 **карточки причин**, которые можно перетащить к своей стопке фишек.

Пример:
- `тонкое вэлью`;
- `давление на capped range`;
- `защита equity`;
- `поляризация`.

Пользователь тянет одну карточку к фишкам.

После:
**РАЗМЕР ✓ / ЦЕЛЬ ✕**

Это визуально другое действие, хотя реализуется обычным drag через Pointer Events.

---

# РЕЖИМ «ДВЕ РУКИ»

В центре один board.

Слева:
`A♠ K♥`

Справа:
`Q♣ J♣`

Ниже большая шкала:
`МЕЛЬЧЕ ←────────→ КРУПНЕЕ`

Пользователь **перетаскивает обе карточки рук** на шкалу.

После приложение показывает reference positions.

Не надо оценивать по одному pixel-perfect значению:
- green zone;
- yellow zone;
- red zone.

---

# RANGE MODE

Показывается 13×13 grid.

Внизу три «кисти»:
**CHECK**
**SMALL**
**BIG**

Пользователь проводит пальцем по grid.

Ячейки окрашиваются семантически.

После:
**СРАВНИТЬ С ПЛАНОМ**

Поверх user-range появляется тонкая рамка reference.

Итог:
- лишние big-bet combos;
- пропущенные value;
- слишком много bluff.

### Важно
Не называть это solver comparison, если reference не solver-derived.
