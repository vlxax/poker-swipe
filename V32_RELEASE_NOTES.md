# PokerSwipe V32 — результаты ремонта по аудиту

Дата сборки: 2026-08-15

## Закрытые критические ошибки

| Область | Было | Исправление V32 |
|---|---|---|
| Запуск | V30/V31 обращались к ядру до его инициализации | Синхронный boot и живой bridge API |
| Хранилище | Ошибки записи скрывались, профили могли смешиваться | Пользовательский V32 key, backup, явный warning, безопасная миграция |
| Skill/Form | Несовместимые выборки и резкий скачок от одного ответа | Baseline с весом 20, до 120 реальных решений, Form по последним 20 |
| Повторные события | Двойной тап и повтор Daily записывали лишние решения | Stable attempt ID и дедупликация |
| Даты/серия | UTC мог менять день, серия не сбрасывалась после пропуска | Локальная дата и проверка непрерывности |
| Swipe | V31 скрывал pot/stack, статичный текст подменял spot | Видимый фактический контекст и честная маркировка dataset |
| Quick/Heal | Таймер продолжал работать после выхода; завершённый курс ломал шаг | Полная отмена сессии и корректный completed-state |
| All-in | Пустые дефолтные карты, нет префлоп-расчёта | Валидные default cards, Worker Monte Carlo, проверка коллизий карт |
| My Hands | Две истории, слабая проверка фактов, опасное удаление | Миграция в одну историю, валидатор, drafts, export, confirm + Undo |
| Hand review | Частоты 0–1 сравнивались как проценты и могли вызвать runtime error | Единая шкала 0–100 и безопасная нормализация |
| Турниры | Bounty терялось в profit, запятая давала 0, слабая валидация | Bounty count/money, decimal comma, return/profit/ROI, field validation |
| X-Ray | Частичный прогон делился на общее число запусков | Собственный denominator каждой метрики |
| Публичные профили | Клиентская запись не подтверждала пользователя безопасно | Синхронизация выключена до verified backend + RLS |

## Дополнительные изменения

- На Home четыре метрики стали интерактивными и объясняют формулу.
- Profile всегда показывает Heal, повтор диагностики, экспорт и импорт.
- Daily честно обозначен как пять проверенных учебных сценариев.
- Статичный режим «3-Max AI» переименован в Policy Sprint, чтобы не изображать игру против AI.
- Реконструктор анализирует только реально достигнутые улицы и не допускает showdown после Hero fold.
- Черновики реконструктора, All-in, диагностики и активной Quick-сессии переживают закрытие приложения.
- Добавлены responsive-правки, заметный keyboard focus и минимальная ширина tap-targets.

## Проверено автоматически

- Синтаксис внешних и всех inline-скриптов.
- JSON manifest.
- Fresh boot и returning-user boot без console/runtime errors.
- Миграция V28 → V32 и сохранение нового state.
- Отрисовка V31 Home и переходы по ключевым экранам.
- Защита Sizing и Daily от дублей.
- Сглаживание Skill и сброс streak после пропуска.
- All-in default cards и ответ Worker.
- Bounty math, decimal comma и детализация турнира.
- Нормализация hand-review policy 0–1.
- Ошибка пустой линии раздачи вместо падения.
- Отмена Quick и completed Heal.

## Осознанно не включено

- Каталог/модуль Kataly — отдельный следующий этап.
- Публичные профили — release blocker до серверной Telegram verification и RLS.
- Полная декомпозиция монолитного `index.html` — потребует отдельной итерации с визуальной регрессией.
- Service Worker/offline cache — manifest добавлен, но offline-режим пока не заявлен.
- Коммерческие solver/ICM datasets — текущий PokerBrain остаётся учебной reference-моделью.

## Ручная приёмка перед production

1. Открыть сборку через HTTPS внутри Telegram Android и iOS.
2. Пройти onboarding/diagnostic и перезапустить Mini App на середине теста.
3. Сделать по одному действию во всех режимах и проверить Profile/JSON export.
4. Проверить All-in на реальном устройстве с доступным Web Worker.
5. Добавить, изменить, удалить и восстановить турнир и раздачу.
6. Проверить safe-area и клавиатуру на малом iPhone и Android 360 px.
