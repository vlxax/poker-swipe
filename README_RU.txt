PokerSwipe — вход по коду из email
=====================================

Новый цикл:
1. Пользователь вводит email в PokerSwipe.
2. Нажимает «ПОЛУЧИТЬ КОД».
3. Код приходит на email.
4. В PokerSwipe открывается экран «ВВЕДИ КОД».
5. Пользователь вводит код прямо в приложении.
6. После успешной проверки показывается «ВХОД УСПЕШЕН».
7. Supabase session + refresh_token сохраняются в localStorage.
8. При следующем запуске приложение восстанавливает сессию и НЕ просит вход заново.

ЧТО ЗАМЕНИТЬ В GITHUB
---------------------
Только файл:

js/pokerswipe-auth-bootstrap.js

ЧТО ОБЯЗАТЕЛЬНО СДЕЛАТЬ В SUPABASE
----------------------------------
Email OTP и Magic Link используют один и тот же email-шаблон.
Чтобы Supabase присылал КОД, а не ссылку:

Supabase Dashboard
→ Authentication
→ Email Templates
→ Magic Link
→ заменить содержимое письма на содержимое файла:
  SUPABASE_EMAIL_TEMPLATE.html

Критично: в шаблоне должна быть переменная:

{{ .Token }}

Если оставить {{ .ConfirmationURL }}, Supabase продолжит присылать ссылку.

После сохранения шаблона:
- дождись GitHub Pages deploy;
- полностью закрой PokerSwipe/Safari;
- открой заново;
- введи email;
- должен открыться экран ввода кода.

ТЕХНИЧЕСКИ
----------
- запрос кода использует существующий Supabase /auth/v1/otp;
- проверка выполняется POST /auth/v1/verify:
  type: "email"
  email: ...
  token: ...
- поддерживаются обе формы ответа Supabase:
  прямой session payload и вложенный payload.session;
- access_token/refresh_token сохраняются;
- при старте существующая сессия восстанавливается;
- старые magic-link callback временно всё ещё понимаются для совместимости.

ВАЖНО
-----
Сам ZIP не может изменить серверный email-шаблон Supabase.
Это единственная серверная настройка, которую нужно сделать в Dashboard.
