# Подключение к текущему PokerSwipe

Заменить действующую реализацию профиля; не подключать второй renderer поверх старого.

1. Найти актуальный владелец `renderProfile` и удалить его старую реализацию из активного пути. Не заменять весь `poker_swipe_v39.js`: в исходнике он содержит Home.
2. Подключить `profile.js` один раз после core и имеющихся инструментов данных. Роутер должен вызывать текущий `window.renderProfile`. Проверить поздние присваивания и удалить относящиеся к старому профилю.
3. Удалить старый блок CSS профиля и подключить `profile.css` один раз. Стили Home/My Hands оставить.
4. Контейнер — `#profileArea`. Источник состояния — `PokerSwipeCore.store.getState()`; fallback `window.S` только для существующего публичного моста. В исходном index.html API подтверждён; предыдущая гипотеза, что window.S обязательно недоступен, была неверной: core экспортирует его через getter.
5. `show` остаётся существующим роутером. Модуль не оборачивает его. Все определения маршрутов находятся в массиве definitions. Сопоставить их с текущей веткой. Несуществующие маршруты становятся обычными строками без кнопки.
6. Сводки используются из S.events, S.hands, S.myHands18, S.healCourses, S.xray, S.tournaments, S.snapshots. Проверить отдельные хранилища Training/Exploit/Daily/My Tournaments в актуальном репозитории. Если они независимы, написать читающий адаптер в model/definitions с дедупликацией. Не копировать их в S ради интерфейса.

## Действия настроек

Экспорт: существующая `window.exportPokerSwipe32()`.
Диагностика: существующая `window.startDiagnostic25(true)` после подтверждения пользователя. Если API отсутствует, кнопка скрыта.
Импорт: `window.importPokerSwipe32(file)`; не реализовывать новую миграцию.
В предоставленном исходном poker_swipe_v32.js importStateFile закрыт в IIFE. Чтобы сохранить импорт при замене профиля, сразу после объявления этой функции экспортировать её:

```js
window.importPokerSwipe32 = importStateFile;
```

Это доступ к существующему импортёру, не новая функция импорта. На текущей ветке сначала проверить, не экспортирован ли он уже под другим именем, и использовать имеющийся API. После импорта исходный импортёр показывает результат и перезагружает приложение. До подключения API кнопки импорта нет.

## Проверка после подключения

- Открыть профиль через настоящую навигацию на 375/390/430 px.
- Завершить упражнение → профиль → новое решение → уйти → вернуться → перезагрузка → запись сохранилась ровно один раз.
- Сравнить счётчики с исходными хранилищами каждого раздела.
- Проверить экспорт, импорт корректного/некорректного файла и отказ от повторной диагностики.
- Измерить document.scrollWidth и геометрию нижней навигации; устранить лишнюю min-height у внешнего контейнера, если она осталась в глобальных стилях.
- Нет нового renderer wrapper, polling, console exceptions, старого профиля после отложенных обработчиков.

## Локальные тесты

```bash
npm install --no-save jsdom
node profile.test.cjs
```

`preview.html` — только изолированное превью с тестовыми данными. Его обработчик переходов намеренно показывает название раздела, не имитирует работу приложения. Не использовать превью как доказательство E2E.
